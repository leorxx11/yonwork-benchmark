# 结论与风险

截至 2026-09-21。这份文件回答两个问题：**现在能说什么**，以及**不能说什么**。

分开写是刻意的。这个项目反复栽在同一件事上——拿到一组看起来正常的数字，
就顺手把它当成结论。下面凡是标「未确立」的，都是**有数据但不足以下结论**，
不是「还没做」。

---

## 一句话

**工具链本身已经可用，并且在搭建过程中查出了 5 个产品缺陷和 2 个我们自己的观测盲区；
但积累的测量数据还太薄（24 轮 / 2 个 Case），不足以支撑任何性能或成本结论。**

换句话说：**能回答「这个东西坏没坏」，还回答不了「这个东西有多快、多贵」。**

---

## 一、已经确立的

### 1.1 工具链能力

| 能力 | 状态 | 证据 |
|---|---|---|
| 批量跑 prompt、逐轮隔离、失败分类 | 可用 | PAD 时代 9 条问题消掉 8 条（见 CLAUDE.md 五） |
| 五层断言 + 按 Case 声明阈值 | 可用 | runner 188 项、web 21 项离线单测 |
| 三来源用量交叉验证 | 可用 | 端上 / 会话 JSONL / NewAPI 后台，互为兜底 |
| 逐轮 ErrorCalls 采集与判定 | 可用 | `docs/error-calls-collection.md` |
| 跨模式一键编排（产品 × 模型） | 可用 | 一次提交 N 个模式，落进同一份对比报告 |
| YonWork + WorkBuddy 同一套断言 | 可用 | 两个产品的工具用例都实测 Pass |
| 耗时拆分（模型 vs 进程冷启动） | 可用 | WorkBuddy 36.38s 中 33.93s 是模型，其余是冷启动 |

**最有说服力的一条不是某个功能，是这几个盲区被抓出来的方式**：
它们都不是靠读代码发现的，是靠「写一个会失败的断言，然后跑一轮」逼出来的。

### 1.2 产品缺陷（5 条，详见 CLAUDE.md 六）

1. **高危：本地服务默认对局域网开放且免鉴权。** 无凭据即可拿到完整登录态
   （accessToken / userId / tenantId / 用户名）。本机已缓解，**产品默认值没变**。
2. `yonworkctl` 路径不匹配，官方 CLI 在这个构建上完全不可用。
3. 端上 `/api/usage/recent-token-history` 漏记；两个独立来源对得上，它是异常值。
4. `modelSelection` 字段名写错时**静默回落默认模型**，HTTP 200、答案正常。
5. `sessionKey` 大小写不一致导致一轮对话被拆成两条会话，界面看不到完整对话。

第 1 条和第 5 条有完整复现数据。**这 5 条是本职工作的主要产出，尚未上报。**

### 1.3 我们自己的观测盲区（2 个，已修）

两个产品**各有一个**「模型明明调了工具，我们却记成 0 次」：

| 产品 | 我们在看哪 | 实际在哪 |
|---|---|---|
| YonWork | `/api/chat/send` 的 SSE，content 块全是 text | 会话 JSONL 的 `{"type":"toolCall"}` |
| WorkBuddy | assistant 消息的 content 块 | 顶层记录 `{"type":"function_call","name":"Bash"}` |

**这类盲区最危险的地方在于它会把责任算错**：断言会判产品 Fail，
而真实原因是我们看不见。已修，并因此更正了一条旧结论
（探针 S5/S6 的 `tool_calls=0` 不能证明模型没调工具）。

## 二、明确**未确立**的

下面每一条都**有数据**，但数据不支持结论。不要引用它们下判断。

### 2.1 两个产品的性能对比 —— 未确立

已有的两组对比都是 **n=1**，而且**两边跑的是不同的默认模型**
（YonWork 走 deepseek-v4-flash，WorkBuddy 走 minimax-m3 / glm-5.3）。
所以那是「产品默认配置」的对比，**不是同模型对比**。

还有一个更硬的障碍：**冷启动不是常数**。同一个 WorkBuddy 驱动实测到过
13.6s、3.34s、2.44s 三个量级完全不同的冷启动。
按协议（CLAUDE.md 七-2.6）这种情况应当报中位数 + 最小/最大，而不是均值，
而目前每种组合的样本数都是个位数。

### 2.2 成本基线 —— 未确立，而且**不要再找单一底噪**

同一句「你好！」的 inputTokens 实测跨度 **5,514 ～ 16,238**（3 倍）；
长文本用例同一轮，会话 JSONL 记 30,082、NewAPI 后台记 228,354（**7.6 倍**）。
所以：

- 全局常数阈值已经删掉，改成按 Case 声明 `max_input_tokens`；
- 没声明就**只记录不判定**，记录下来的值是将来定分位数基线的原料；
- **跨来源比数字没有意义**，两个来源统计口径就不同。

现在库里 21 条 session-jsonl 样本的 input_tokens 跨度是 5,514 ～ 33,237。
**样本太少，还不能定阈值。**

### 2.3 客户端是不是瓶颈 —— 未确立（探针已结项）

21 轮记录里最长 Long Task 是 182ms，低于预注册的 200ms 阈值，
但 S4 的三次值 79 / 88 / 182ms 跨度大于中位数，**按协议应标样本不足**。
更关键的是：**API 发起模式量不到用户感知延迟**——
UI 对照观察到 18 次流式更新，API 批次只有 1～2 次，
首字滞后里混进了后端剩余生成时间。

所以「客户端不是瓶颈」**没有被证明**，「客户端是瓶颈」也没有。
这是个未决问题，不是已排除项。详见 `docs/client-probe-results.md`。

### 2.4 覆盖面 —— 很薄

库里累计 **24 轮、2 个不同 Case、13 个实验**。
判定分布 Pass=22 / Fail=1 / Error=1，其中那 1 个 Fail 和 1 个 Error
都是调试过程中的产物，不是产品缺陷。

**这个体量只够证明链路通，不够做任何统计。**

## 三、风险

按「会不会产生假数据」分档。第一档最危险——它们不报错。

### 3.1 会静默产生假数据的（最高优先级）

| 风险 | 后果 | 现状 |
|---|---|---|
| **时间窗匹配依赖串行** | NewAPI 用量张冠李戴，数字看着正常 | 已用 MySQL 咨询锁强制单 Worker。**并发跑批会直接破坏正确性**，不是性能问题 |
| **同一模型可能落成两列** | 报告里「不指定模型」和「显式选那个默认模型」是两个 `model_mode`（`default` vs `默认模型`），实际跑的是同一个模型 | 库里已经出现（13 轮 vs 1 轮）。**两者请求路径确实不同**（发不发 `modelSelection`，关系到缺陷 4），所以分开记不算错，但**横向对比时会重复计数** |
| **新产品接入时漏改报告查询** | 那个产品的 token 整列为空，症状和「端上漏记」一模一样 | 已加结构性回归：`USAGE_SOURCES` 里每个值都必须出现在报告查询里 |
| **驱动漏实现协议方法** | 静默少一份原材料 | `batch` 对 `enrich` 的 `AttributeError` 不吞，会当场炸 |
| **选择器随客户端升版失效** | 探针数据悄悄变质 | 选择器按 1.0.8 校准过；改版后**必须重校**。用语义选择器而非坐标，找不到会报错而不是点错 |

### 3.2 限制结论适用范围的

- **只有一台机器、一个账号、一个网络环境。** 所有数字都是这台个人笔记本上的。
- **WorkBuddy 的「当前工作目录」是 `\\wsl.localhost\...` UNC 路径**，
  CMD 不支持、会回落到 Windows 目录。跨产品比「列出当前目录」这类用例前
  **必须先把工作目录定死**，否则两边问的不是同一个目录。**未解决。**
- **模型输出不能直接断言**，所以内容层只做弱断言（禁止词 / 期望关键词 /
  长度下限 / JSON 可解析）。**断言通过不等于答案正确。**
- **`--max-turns` 会影响可比性**：关工具 1 轮、开工具 8 轮，不是同一种约束。

### 3.3 安全与操作

- ⚠️ **`bypassPermissions`**：勾选「允许调用工具」后，那一批跑批期间
  模型可以在这台 Windows 上**执行任意命令**。默认关闭，前置检查会打警告。
  用例 prompt 是自己写的、Git 版本化的，所以风险可控但**不为零**。
- ⚠️ **缺陷 1 只在本机缓解，产品默认值仍是 `0.0.0.0` + `trusted`。**
  换台机器、或者重装后没重设那三个环境变量，局域网暴露就回来了。
- **跑 WorkBuddy 必须切到宿主机 Worker**，且切过去之后不能用裸
  `docker compose up -d`（worker 是 `restart: unless-stopped`，会被拉起来抢锁）。

## 四、如果只看三件事

1. **上报那 5 条产品缺陷**，尤其是第 1 条（局域网免鉴权）和第 5 条
   （sessionKey 大小写，有完整复现数据）。这是本职产出，拖久了价值会掉。
2. **攒数据**。现在 24 轮 2 个 Case，什么阈值都定不了。
   要定分位数基线，得先让同一个 Case 在同一模式下跑够样本。
3. **别把「链路通了」说成「测出来了」**。目前每一组对比都是 n=1
   且跨模型，只能证明工具链能跑，不能证明任何性能差异。
